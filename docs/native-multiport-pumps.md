# 原生多端口泵与储液源输送

本轮替代先前每刻相邻 drain/fill。AdjacentFluidTransfer 及其异常恢复测试删除；不再有新相邻转移失败后生成恢复包裹的逻辑。

万向泵使用 FluidTransportBehaviour，输入／输出面提供对应压力。无输入、无输出、无动力不提供驱动压力；不注册 IFluidHandler，不拥有2000mB储罐。源流体通过原生流动建立与 FluidNetwork 直接到目标，堵塞不转存到泵内。旧Buffer存档内容一次性导出为真实流体包裹（迁移，而非异常搬液恢复）；待迁移内容在保存前仍保留Buffer键。

缓存泵保留有限缓存，创造输送储罐保留无限源。StoredSourceTransport以内部源连接与真实输出连接驱动原生PipeConnection/FluidNetwork，直接贴容器或开放口也可运行，不强制添加管道。内部连接提供自身储液，不访问背面容器；只有实际输出面参与外部连接。开放口及网络保存遵循原生行为，不再用这些设备自己的PumpOpenEnds。

PnP下，跨管网储液源仍由引擎接管；当输出直接面对终端、没有管道／万向泵时，允许该储液源原生传输运行。万向泵作为泵节点提供强度，按真实端口映射求解器吸排侧，禁用水轮机自动角色。多输出执行和多输入供液已联测，但PnP内部部分渲染、沉降辅助仍只记录一个主要pushCell/pullCell，所有复杂分叉／环路与严格共享速率上限尚未全量验证，不能等同原端点预算实现。Create侧输入压力按输入数分摊以限制总入口驱动力。

原“万向泵共享缓存及每刻预算”已移除；吞吐由原生压力与网络分配决定，不能保证所有管网拓扑都与旧固定预算完全相同。PnP管内可有真实储液，停泵／堵塞后已有管内容物仍可沉降，非泵内缓存。

原生Create与PnP3.2.1环境均116项GameTest通过：直接容器、跨管、无输出、满罐、多输入、多输出和守恒、创造世界模式。未客户端联调、未更新JAR。历史性能数据对应旧带缓存万向泵，不能作为本实现性能结论。旧PumpOpenEnds保存的半桶输出载荷不再读取，旧版升级前应停止排液并完成开放口积液；尚未提供该旧输出暂存的迁移。
