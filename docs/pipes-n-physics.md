# Pipes’n’Physics 兼容

适配并联测 PnP 3.2.1 发布包。PnP 是可选依赖，当前兼容范围限制为 3.2.x；未安装时可正常加载。开发环境可通过 `-PpnpJar=/path/to/pipesnphysics-3.2.1.jar` 使用本地发布包，否则从 Modrinth Maven 获取编译依赖。发布 JAR 不包含 PnP。

## 传输与端点

- PnP 开启引擎时负责管道传输，CCD 不再运行原生端点压力传播。端口／速度变化通知 PnP 唤醒和更新缓存拓扑，不添加每刻管网遍历。
- 缓存泵不再被 PnP 误判为透明贯通泵。它和万向泵是有限储液端点；由侧面接口限制输入、输出和共用预算，通过水力边界基准提供动力压差。创造储罐声明为无限 relay 源。
- 普通 CCD 泵直接提供实际动力和方向；变流量系列使用配置的有效压力，双向泵读取反转语义。CCD 泵不自动作为 PnP 水轮机运行。
- 直角泵补充真实吸液端，求解器与实际执行共用同一吸液位置。直角输送通过实际流量及含管内储液的守恒测试。
- 红石阀同步 PnP 开度；过滤仍由流体接口及 PnP 对原生 `canPullFluidFrom` 的检查执行。
- 流量计读取 PnP 执行后的每条边实际 mB 数，不使用管内视觉流速。该数遵循 PnP 的边界最大实际移动量定义，包含管道充液／沉降，不能等同于同刻远端容器净增量。

## 行为边界

PnP 中管道存有真实流体；停泵后管中已有流体可能继续沉降，泵本身停止供液。液面、吸程、粘度和管阻遵循 PnP，因此吞吐不保证等于原生 Create，也不保证原生配置的方块距离就是 PnP 的最大扬程。

同一 PnP 连通网络只要有处于“仅容器”模式的创造储罐，执行时所有开放管口均拒绝接收流体；它不会阻止该网容器之间的输送。这是网络级策略，混合普通源时也生效。切换为世界模式后允许开放管口输出。直接相邻容器／世界输出继续使用固定相邻接口检查，不重复执行管道输送。

兼容使用 PnP 内部拓扑、边界及执行接口，因此升级其内部实现需要重新联测。客户端动画、完整可选模组组合、气体浮力和运动子空间未在本轮验证。

## 验证

84 项 CCD GameTest 在以下环境全部通过：无 PnP；PnP 3.2.1 引擎开启；PnP 3.2.1 引擎关闭。无 PnP／关闭引擎时，2 项 PnP 专用测试直接跳过，其余测试执行原生路径。

新增专用测试覆盖直角泵实际跨弯输送与守恒、创造储罐远端开放管口模式切换。既有测试覆盖端点源供液、万向泵跨管道取送与含管内容积的守恒、停转、红石阀开关、流量计读数及堵塞归零。尚未覆盖所有泵朝向／反转组合、所有过滤器与第三方容器组合。
