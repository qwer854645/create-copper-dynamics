## 1. 一句话结论

现在的做法是 **能引用 Create 原生贴图就不自己画**：

- 11 个「平铜/黄铜/机件面」在模型里直接指向 `create:block/copper_underside`、`brass_block`、
  `industrial_iron_block`，CCD 里对应的 png **已删除**；
- 只有 4 张因为像素布局承载语义（轴孔、同心凹槽、32×32 面）必须保留，且全部由
  Create 的像素派生或按几何生成，**没有引入新调色板**；
- 智能储罐 4 张从 Create 的 `fluid_tank*` 出发，只做色阶换色；
- **流体传讯器 3 张已回退**到返修前的设计，理由见 §9。

## 2. 为什么要动：三处结构性错误

原贴图的丑不是画功问题，是三个可定位的错误。

### 2.1 对称化把机壳做成万花筒

`tools/symmetrize-fluid-housings.py` 曾用 6×6 的 `PATCH` 双向反射 + 90° 旋转生成 16×16 面，
并在结尾断言：

```python
assert image.tobytes()==image.transpose(FLIP_LEFT_RIGHT).tobytes()
assert image.tobytes()==image.transpose(ROTATE_90).tobytes()
```

16×16 有 256 个像素，折两次只剩 **10 个自由像素**。实测 `booster_pump/body.png` 与
`fluid_transmitter/body.png` 的 `LR/UD/R180/R90` 差异**全部 0.0%** —— 四向完全对称，
读起来是模糊的径向渐变而不是金属板；断言还顺带禁止了左上打光。

（`booster_pump/body` 已改为引用 Create；`fluid_transmitter/body` 连同它的 side/top 一起回退
到原设计，见 §9 —— 那三张靠四角铆钉和黄色指示面板撑住了可读性，不是纯粹的糊面。）

### 2.2 换色用绝对亮度阈值，把 8 阶压成 3~4 阶

`recolor-smart-fluid-tank.cjs`、`repaint-smart-tank.py`、`recolor-fluid-arm.cjs` 都用固定亮度梯子分档：

```js
const thresholds=[35,55,75,90,108,128,150,180];
let index=thresholds.findIndex(t=>luminance<t); if(index<0) index=8;
```

Create `fluid_tank.png` 的 8 个铜色亮度是 86.4 / 94.0 / 104.5 / 113.1 / 123.3 / 131.7 / 140.0 / 149.0，
套进去得到 `[3,4,4,5,5,6,6,6]` —— **只剩 4 个不同输出**，而且目标色板比源色亮 70~100，
暗部全丢，于是储罐像刷了层金漆。`recolor-fluid-arm.cjs` 的梯子更糟，8 阶只剩 3 阶。

### 2.3 手绘底板 = 2px 平涂边框 + 一块低振幅色块

`create-faucet.cjs` 的外圈 2px 全写死 `copper[4]`，而 `copper[]` 相邻两阶只差 7~15，
16px 尺度上看不出来。最平的一张 `copper_water_supply/body.png` **79.7% 的像素是同一个颜色**，
只有 3 种颜色。

## 7. 复现 / 校验

```powershell
$jar = "<create-1.21.1-6.0.10-280.jar>"

# 派生贴图
python tools/copper-material.py src/main/resources/assets $jar
python tools/copper-material.py src/main/resources/assets $jar --check    # 只看指标
python tools/copper-material.py src/main/resources/assets $jar --verify   # 比对，有偏差返回 1

# 智能储罐换色
python tools/recolor-rank.py $jar

# 增压泵原生轴孔
python tools/symmetrize-fluid-housings.py
```

验收门槛（16×16 不透明金属面）：`std ≥ 15`、`flat ≤ 30%`、`tones ≥ 6`、
`LR/UD/R180/R90` 至少一项 > 5%（禁止全向对称）。

## 8. 已知取舍

1. **平铜面全部长一样**。所有「一块铜板」的面现在都是 `copper_underside`，靠几何（12×12 内嵌、
   外框、折边）区分而不是靠贴图。这正是 Create 自己的做法（所有 andesite casing 同款），
   但如果你希望每个方块有各自的铜面，需要再引入 2~3 张变体。
2. **智能集液栅 32×32 面有十字缝**。`brass_block` 是 16×16，2×2 铺贴会看到四块板的接缝 ——
   这是它自带边框造成的，视觉上读作「四块黄铜板拼接」。
3. **移液臂贴图没有重跑**。`recolor-fluid-arm.cjs` 的映射已改成秩映射，但 `mechanical_arm.png`
   保持原样：它 `std 54.4`、结构匹配 0.98，本身已达标，重跑需要 `sharp` 且会牵动针管模型，
   收益不划算。改动生效需要下次跑那个脚本。
4. **12 个 `create-*.cjs` 里还留着旧的 `copper[]` 数组**，它们生成的贴图已无人引用。没有删，
   是因为删掉会改变模型生成流程，而本机跑不了 `sharp` 无法验证；改成在文件头声明归属。
5. **未构建、未启动游戏**。全部为离线像素与资源校验：166 个 JSON 全部可解析、
   0 处悬空贴图引用、0 个 blockstate 指向不存在的模型。

## 9. 流体传讯器：已回退

第一版把这个方块的 32×32 面也换成了 `copper_underside` 2×2 铺贴，用户反馈「有点丑」，回退。
原因是那次替换除了观感，还丢了一个功能特征：

| | 返修前（现恢复） | 第一版（已废弃） |
|---|---|---|
| 32×32 面的中心 | **黄色指示面板** + 深色描边、四角铆钉 | 无，被铜板覆盖 |
| 箭头标记 | 位于设计好的位置 | 压在 2×2 铺贴接缝上，读成一坨十字 |
| `side` / `top` 的 std | 39.1（16 色） | 19.6（9 色） |

已回退的文件：`block/fluid_transmitter/{body,side,top}.png` 与
`models/block/fluid_transmitter.json` 的 `body` 键，全部恢复到 `f6e8ff2` 的版本。
`tools/copper-material.py` 与 `tools/symmetrize-fluid-housings.py` 里对传讯器的派生逻辑已删除，
不会再被重跑覆盖。

**结论性教训**：带指示灯、刻度、箭头这类「信息像素」的面，不能套通用金属板；
`copper_underside` 只适合纯结构面。

## 10. 集液栅改成一格高之后的贴图

`d48566a` 把两个集液栅从 8px 深的水盆改成 16px（一格高），`tools/resize-collection-grates.py`
在改几何的同时把侧壁 UV 一起放大了（`uv[3] = uv[1] + 6`），所以侧壁现在是 **一个模型像素对一个纹素**。
继续套 `copper_underside` 就出问题了：

| 现象 | 原因 |
|---|---|
| 两层墙壁读成一整块平板 | 上层采样 v3..9、下层采样 v5..11，而 `copper_underside` 没有垂直衰减 |
| 悬挑底面是**亮**的 | 悬挑底面采样 v1..3，而 `copper_underside` 的高光正好在第 1 行 |
| 凸沿只是一条平色带 | 凸沿上表面只采样最外 2 行/2 列，那圈在原图里没有设计 |
| 智能版凸沿发绿、有接缝 | 用的是 `brass_block` 2×2 铺贴，采样的 v2..3 正好是拼缝 |

改为 `tools/create-collection-grate-textures.py` 按模型的采样条带专门排布：

| 贴图 | 条带 | 设计 |
|---|---|---|
| `copper_collection_grate/wall.png` | v0..2 悬挑底面 / v3 上层顶边 / v5 层间接缝凹槽 / v7 地板侧沿 / v9 上层底 / v11 下层底 | 垂直衰减 + 层间暗缝 |
| `copper_collection_grate/rim.png` | 最外 2 行/2 列组成的环 | 外圈亮倒角 + 内圈暗影线 |
| `smart_collection_grate/body.png` | v2..3 | 黄铜凸沿侧面亮带 |
| `smart_collection_grate/rim.png` | 环 | 同上，黄铜色 |

模型的唯一改动是 `copper_collection_grate.json` 的 `copper` 键：
`create:block/copper_underside` → `ccd:block/copper_collection_grate/wall`。几何、UV 未动。

关键约束：`v3..9` 与 `v5..11` 在 5..9 重叠，所以那几行被两层共用，不能分开调。
第 5 行同时是「下层墙顶（在悬挑下面，应该是暗的）」和「上层墙顶下方 2px」，
两者都偏暗，于是定成一条刻意的凹槽。

预览：`outputs/texture-rework/collection-grate.png`（`git HEAD` 前后对照，4 个视角）。

Python 版（同样的面角顺序、UV 基准四边形、v=0 在图像顶部、光照与 z-buffer 规则），

## 11. 流体舱口：继承物品舱口模型后的贴图

`6e4f834` 把两个舱口模型换成一行 parent 引用：

```json
{"parent": "create:block/item_hatch/block_closed"}
```

没有任何贴图覆盖，所以两个方块都渲染得和 Create 物品舱口完全一样。父模型只开放 3 个键：
`0`（房体，32×32 图集 `hatch.png`）、`1`（闸门，16×16 `hatch_closed.png`）、`particle`。

### 两个渲染探针测出来的事实

**① 正面是 `#0`，不是 `#1`。** 把 `#0` 涂成品红、`#1` 涂成青色后渲染：

| 视角 | 品红（#0 房体） | 青色（#1 闸门） |
|---|---|---|
| 正面 | 整个面板 | 无 |
| 侧 3/4 | 整个可见面 | 无 |
| 俯视 | 其余部分 | **只有斜门的顶面** |

所以「管口」必须画在 `#0`。第一版我把凹槽画在闸门上，从正面一个像素都看不到。

**② 可见面板在图集里的窗口是 x3..15 / y3..17。** 帧的 north 面 uv 为 `[1.5,1.5]-[7.5,8.5]`，
图集 32px → uv×2。这块窗口内部 x5..12 / y5..14 是 Create 画的**物品格栅百叶**。

### 做法

| 文件 | 做法 |
|---|---|
| `block/{fluid,smart_fluid}_hatch/housing.png`（32×32） | Create `hatch.png` 的**中间灰**换成铜/黄铜，黑与银原样保留 |
| `block/{fluid,smart_fluid}_hatch/flap.png`（16×16） | `hatch_closed.png` 同上 |

### 三次返工的教训

**第一版：整体亮度重映射。** 把三档材质全压到一条铜色阶上，用户反馈"像是直接加了滤镜，有点奇怪"。
Create 的舱口美术其实分三档：

| 亮度 | 材质 | 占比 | 处理 |
|---|---|---|---|
| ≤ 56 | 黑色凹槽 / 格栅缝 | 11% | 原样保留 |
| 56~145 | 工业铁本体 | 78% | 换铜 / 黄铜 |
| ≥ 145 | 裸银高光 / 包边 | 8% | 原样保留 |

只换中间灰之后，格栅结构和银色包边都回来了（色阶数从 10~11 回到 17~18）。

**第二版：在正面面板压一个凹陷管口。** 也不对。那个窗口（x5..12 / y5..14）正是 Create 画的
物品格栅百叶，压一个洞会把结构盖掉、看起来像铜板上挖了个方孔。已放弃。
如果后续要加强"流体"语义，建议在角落加一颗小水滴标记，不要动门面本身。

**色阶是同一把梯子上的一段切片，起点决定深浅。** 这一点来回调了三次，记下来避免下次再绕：

| 起点 | `std` | 反馈 |
|---|---|---|
| `#3D161E`（亮度 31，10 阶） | 53.7 | "颜色看起来太深" |
| `#9A5038`（亮度 94，7 阶） | 59.0 | "又有点浅" |
| **`#724731`（亮度 79，9 阶）** | **55.0** | 采用 |

第一次以为是自己压暗了，实测换色的 441 个像素平均亮度只差 +3.3，说明**问题不在数值，而在
饱和的铜色比同亮度中性灰看起来更沉**。但把起点一路抬到 94 又走向反面：切片只有 7 阶、
跨度 55，本体丢掉色阶、发平，于是"浅"。

所以正确做法不是"提亮"，而是**在亮度与切片长度之间取中间**：起点 79、跨度 70、9 阶。

| 材质 | 色阶 |
|---|---|
| 铜 | `#724731` → `#E3826C`，9 阶 |
| 黄铜 | `#724731` → `#FFEB8C`，12 阶 |

每个颜色都是 Create 真实存在的色，没有插值。要微调就换起点：往亮一档 `#904931`，
往暗一档 `#6C3528`（取自 `mechanical_arm.png`）。

### 过滤槽位

用户已把过滤槽位改成 Create 原生 `HatchFilterSlot`。从它的字节码常量看是
`Vec3(8.0, 5.15, 9.5)`、`-45°`、`0.965` —— 图标跟着斜门一起倾斜，贴在门上，**不在正面面板上**，
所以不会和贴图打架。

### 智能版专属：黄铜包边

只给 smart 版加。Create 的黄铜件从来不是一张平黄铜板，而是**亮金框 + 内凹暗面**
（`brass_casing` 是这种语法的极端版）。不加包边的 smart 版就只是"铜版换了个颜色"，
没有任何读作黄铜五金件的特征。

**第一版压错了窗口。** 我压的是 `x3..15 / y3..17`（帧的 north 面），那是**贴着容器的那一面**，
模型预览看着对，游戏里根本看不到。舱口实际的可见面是墙体的两面（`element 0` 的 north 与 south
共用 `x2..15 / y2..17`）。现在两个窗口都压：

| 窗口 | 是谁 | 说明 |
|---|---|---|
| `x3..15 / y3..17` | 帧 north 面 | 贴容器那侧，压了也不亏 |
| `x2..15 / y2..17` | 墙体 north + south | **玩家实际看到的那面** |

> `x16` 和 `y18` 在 Create 的原图里是透明像素，所以墙体窗口的实际画布是 `x2..15 / y2..17`。

每道环：最外 1 像素 `#FBDC7D`（亮金），第 2 圈 `#724731`（暗缝）。只动最外两圈，
物品格栅不受影响。试过 3px，会啃掉格栅、显得笨重。

铜版不加包边——两个变体正好靠这一点区分。

### 最终版本：撤回重画，只换色

用户反馈"背面太难看，正面太乱。尽量不要打乱纹理"。

前面几版（描边框 → 三层次加凹槽 → 门板倒角）都在改 Create 原有的像素布局：给凹槽压石板灰、
给框描边、给门板做倒角。改动越多，正面越乱、背面越闷。

所以全部撤回，**只保留材质替换**：`swap_material()` 只动中间灰，黑色格栅、银色包边、
亮边和暗缝一个像素都不挪。框的层次感不再靠我画，而是靠 Create 本来就有的亮边和暗缝
加上黄铜色阶的跨度自然形成。

试过三档色阶起点（`724731` / `592424` / 更长的 `443018`+`592424`）：后两档会把暗缝推向
脏褐、反而更闷，所以保持 `724731`。

### 最后两档：铜提亮，黄铜改用动力臂配色

用户："铜的太深了；黄铜可以参考动力臂的颜色。"

**铜**：起点从 `#724731`（亮度 79）提到 `#9A5038`（94），7 阶。
之前"重画版"时代在 94 起点上判断过"有点浅"，那是错误的对比对象——当时上面还叠着我画的
描边和凹槽，把整体推亮了。回到纯换色后 94 才对。

**黄铜**：换成 `create:block/mechanical_arm.png` 的暖色阶，`#724731` → `#F7CB6C`，**15 阶**。

| | 亮度 78~116 之间的中间色 |
|---|---|
| `brass_block` | 只有 `#724731` → `#9E6947`，一步跳过 |
| 动力臂 | `#854A34`、`#875137`、`#8E5B3D`、`#995A3D`、`#A46B47` 五档 |

多这几个台阶，本体才有"机加工黄铜"的层次，而不是一张平金箔。

### 最后一版：真的改细节像素，做倒角

用户："我说了可以在细节上改变像素，现在版本说实话并不好看。"

**纯换色为什么必然糊**：Create 的 hatch 原图是**灰色**设计，靠细腻的明度差堆出结构。把灰直接
映射成黄铜，那些"细腻的灰差"就变成"糊成一片的金"——这是换色方案的天花板，再调色阶也救不回来。

所以加一道 `bevel_details()`：沿 Create **已经画好的**每条边（外轮廓、面板边、每根格栅），
在上侧加亮、下侧压暗。

这不是重画，是**改已有像素的明度**：边缘位置一个都没动，没有增删任何像素，布局完全保留。
判据是相邻像素的亮度跳变（`EDGE_JUMP = 14`），幅度 2 档（`BEVEL = 2`）。

比过四档（纯换色 / 倒角 / 5 色量化 / 倒角+量化）：量化会把本体拍成塑料块，倒角+亮色阶最稳。

预览：`outputs/texture-rework/fluid-hatch.png`（Create 原件 / 铜版 / 黄铜版 × 三个视角）。

## 13. 智能储罐：改成"黄铜机壳"感，去掉木质感

用户反馈"智能储罐有点太丑"，随后明确要求"做成类似黄铜机壳那种感觉，但是不要木头元素"。

### 为什么之前丑

`recolor-rank.py` 把 Create 储罐的 8 阶铜色按秩映射到 8 阶黄铜。两套色阶的亮度跨度不同：

| | 亮度跨度 |
|---|---|
| Create 铜色 8 阶 | 86 → 149（63） |
| 原来用的黄铜 8 阶 | 79 → 174（95） |

同样 8 个色阶摊在 1.5 倍跨度上，Create 那点细腻的铜面纹理被放大成噪点：顶面成了随机斑点、
侧面成了明暗横条。数字上 `fluid_tank` 的 `std` 是 **30.5**，而 Create 原版只有 **18.7**。

颜色也偏橄榄褐：原来的色阶最高只到 `#D7AA5E`，**从没用过 Create 黄铜真正的亮金**
（`#F7CB6C` / `#FFEB8C`）。

### 为什么"黄铜机壳"会带木头感

`brass_casing` 的层次来自 `#442B15`、`#53381A` 这些**低饱和暖褐**，在小尺寸上读起来就是深色木板。

### 做法：按机壳语法重映射，暗部换中性金属

Create 的 `fluid_tank.png` 结构本身就是机壳式的：

| 行 | 内容 |
|---|---|
| 0~2 / 4 / 13~14 | 亮带 |
| 3 / 12 / 15 | 暗缝 |
| 5~11 | 中段本体 |

于是 8 个色阶分成两段：

| 源色阶 | 目标 | 取自 |
|---|---|---|
| 最暗 4 阶（0~3） | `#2B2B2E` → `#494848` 中性灰 | `industrial_iron_block` |
| 最亮 4 阶（4~7） | `#BF8E55` → `#F7CB6C` 黄铜金 | `brass_block` |

暗部是**纯中性灰**（饱和度 0~4%），所以完全不发木；亮部是黄铜金，形成"金框 + 金属暗板"的机壳感。

试过三种分段（4 暗 + 4 金 / 2 暗 + 6 金 / 3 暗 + 5 金）。2 暗那版更偏"黄铜储罐"而不是"机壳"；
3 暗那版中段仍偏暖，还是有点木。

### 取舍

第一版做成了**整块黄铜 + 中性灰暗板**（std 56.7），看着像黄铜机壳，但用户澄清想要的是
**"有黄铜机壳的铜储罐"**——铜身要保留，只有框是黄铜。

### 最终做法：按行分区，铜身不动

Create 的 `fluid_tank.png` 行结构正好能分区：

| 行（16px 侧板） | 区域 | 材质 |
|---|---|---|
| 0~2 / 4 / 13~14 | 横向框带 | 黄铜金（`brass_block` 金段） |
| 3 / 12 / 15 | 板缝 | 中性灰（`industrial_iron_block`） |
| 5~11 | 板面 | **Create 原铜色，一像素不动** |

顶盖原本只有 1px 黄铜细线，用户要求"顶部也包裹黄铜机壳"，改为 **2px 黄铜框 + 1px 暗缝**，
语法与侧板框带一致。内壁保持原样（几乎看不到）。玻璃窗贴图直接保留 Create 原样。

### 所有棱都包黄铜（第二轮：竖向太浅 + 高塔横条）

用户接着反馈两个问题："纵向的棱上的包边太浅"、"储罐高一点之后横向有很多横向的条，很丑"。

**`fluid_tank.png` 是一张边框图集，不是一整张面。** 从模型 UV 读出来：

| 区域 | UV | 实际用途 |
|---|---|---|
| 第 0~3 行 | `[0,0,16,4]` | 顶盖的侧带（横向棱，上） |
| 第 12~15 行 | `[0,12,16,16]` | 底部带（横向棱，下） |
| 第 0~3 / 12~15 列，4~11 行 | `[0,4,4,12]` / `[12,4,16,12]` | 竖直棱条 |
| 中间 4~11 行 | — | 被玻璃窗挡住，模型不采样 |

上一版把整张 16×16 当一整面描边，等于给模型根本不会读的像素上色，真正的横带反而没处理对。

**两个问题同一套解法：横竖分色，不再同宽同亮。**

| 轴 | 取值 | 原因 |
|---|---|---|
| 竖直棱 | 亮金 `#E4B763` → 次亮 `#D7AA5E` → 1px 暗缝 | 竖向是每块自己的角柱，做深一点才不"浅" |
| 横向棱 | 暗金 `#C79758`（仅 2 行） | 横向棱和上下方块共用，每层亮金就会变成一摞横条 |

竖直棱的深度靠三像素渐变 + 一道暗缝做出倒角，平涂一条亮色会显得贴上去。

48×48 连接面板同一逻辑：外圈 2 列亮金、上下 2 行暗金、再一圈暗缝。

预览：`smart-fluid-tank.png`、`smart-fluid-tank-multiblock.png`、
`smart-fluid-tank-ct.png`（另 `1×1×5` 长柱见 `E:\ds\preview\tank_column.png`）。

### 多方块：64px 的 CT 图不是 16px 图块网格

单方块做好之后，多方块版本还是错的——**64×64 的 `*_connected` 图被当成了 4×4 的 16px 图块网格**，
于是每一格都被套了一个黄铜环，一整块连续面板被切成可见的 3×3 格子。

实际布局（读 Create 原图确认）：

| 区域 | 位置 | 内容 |
|---|---|---|
| 连接面板 | `x16..63 / y0..47`（48×48） | **一整块连续面板**，九宫格拼成的整体 |
| 独立面 | `x0..15 / y48..63`（16×16） | 普通 16px 面 |
| 其余 | — | 透明 |

所以按**区域**而不是按图块分区：

- `fluid_tank_connected`：48×48 面板的肋带行（亮带 `0..2,4,9,25,41,45`、暗缝 `3,8,24,40,44,47`）
  换成黄铜/中性灰，面板外圈 `2px` 黄铜；左下 16×16 走和独立面一样的语法。
- `fluid_tank_top_connected` / `fluid_tank_inner_connected`：只给 48×48 区域**外圈**一圈框
  （顶盖 `2px + 1px` 暗缝，内壁 `1px`），这才和 Create 原图"一整圈大框"的结构一致。

预览：`outputs/texture-rework/smart-fluid-tank-multiblock.png`（2×2×2）、
`smart-fluid-tank-ct.png`（三张 CT 原图与重制对照，叠了 16px 参考线）。

> 预览渲染的是**逐方块模型**，没有模拟 Create 的 CT 选中逻辑，所以 2×2×2 的顶面会显示
> 每格一个框；游戏里相邻方块会改用上面的连接面板，实际是按整块连续面板走的。

板缝试了三档灰度，最深那档像黑洞，取中间档（`#353438`..`#4F4F4F`）读作阴影。

工具从 `recolor-rank.py` 改名为 `create-smart-tank-textures.py`——它已经不是"按秩换色板"了。
`repaint-smart-tank.py` 仍是它的旧入口包装。

预览：`outputs/texture-rework/smart-fluid-tank.png`（Create 原版 / 铜身+黄铜框 × 3 视角）。

模型文件只加 `textures` 覆盖，几何与 UV 未动：

```json
{
  "parent": "create:block/item_hatch/block_closed",
  "textures": {
    "0": "ccd:block/fluid_hatch/housing",
    "1": "ccd:block/fluid_hatch/flap",
    "particle": "ccd:block/fluid_hatch/housing"
  }
}
```

## 12. 潮涌箱：偏淡

用户反馈"潮涌箱的贴图看起来太淡"。

### 两个原因

**① `body` 用错了贴图。** `copper_water_supply/frame.json` 的 UV 是**按边框图集**采样的：

| 元素 | 采样窗口 |
|---|---|
| `copper_base` 四侧 | `v14..16` |
| `copper_top` 四侧 | `v0..2` |
| `copper_post` 四侧 | `u0..2` / `u14..16` |

换成 `create:block/copper_underside` 之后，`v14..16` 正好是那张图的**反弹光带**
（`#D67B5B` / `#E3826C`），于是每个箱体侧面都是一条亮带，整块发白。

现在给它一张专用边框图 `block/copper_water_supply/body.png`，按模型的切片方式排布：
外圈暗缝 → 一像素亮倒角 → 下方压暗。

**② `cap` 把三个环都用在高光上。** `cap` 同时用于顶面圆环和 12×12 凹槽底
（两个面都是整张 0..16 UV），所以它必须读成"框 + 下沉的中间"。旧版 ring0~2 全是亮色，
高光面积太大。现在只有 1 像素是亮倒角，其余是暗缝 + 下沉地面 + 中央排水口。

### 深度

改完仍然偏浅，所以把整块铜压深一档。以渲染后整块的平均亮度为标尺：

| `SUPPLY_TONE_SHIFT` | 平均亮度 | 结果 |
|---|---|---|
| 0 | 95.0 | 仍偏淡 |
| **-1** | **88.5** | 采用 |
| -2 | 84.1 | 顶面细节糊掉 |

预览：`outputs/texture-rework/copper-water-supply.png`（`git HEAD` / 现在 × 3 视角）。
