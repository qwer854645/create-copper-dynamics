# 流体舱口模型

普通流体舱口采用用户选择的 A 方案：去掉原生斜面与多层框架，使用贴壁的薄铜板 [2,2,0]–[14,14,2]，中央配朝外的原生流体管口。管口直接使用 Create 6.0.10-280 的 `fluid_pipe/rim_connector/south` 与 `fluid_pipe/rim/south` 几何及 UV，只沿 Z 轴平移 -12，不缩放或倾斜，端面中心位于 [8,8,4]。内部管口不处于方块边界，因此移除其邻块裁切标记。整个模型只有铜板、原生连接段与原生端圈三个元素，不加铆钉或装饰环。物品显示变换继续继承原生舱口。

`plate.png` 为 16×16 像素图，沿用 CCD 已有 `faucet/body` 的不规则铜色像素簇，用 pixel-art 技能逐像素增加一像素的亮边和暗边，表现薄铜板折边，不使用渐变或抗锯齿。旧的原生舱口改色图集已移除。

管口侧壁与端面直接引用原生 `pipes.png`，始终露出深色管孔，不使用内盖、开合贴图或舱门动画。移除原来的灰色内盖派生贴图与开启模型。

普通版和智能版在手持容器交互成功后只播放原生音效，不切换 OPEN，不安排 10 tick 复位。为继续继承 ItemHatchBlock，保留父类构造要求的 OPEN 属性，但它不参与 CCD 的交互和模型选择；方块状态资源只按四个水平方向选择固定模型。含水、安装、扳手、手持容器取放及后方容器访问逻辑继续沿用既有实现。普通版物品模型继续继承固定管口模型。

普通版选取与碰撞由铜板 [2,2,0]–[14,14,2] 和端圈 [3,3,2]–[13,13,4] 合并，使用 Create 自带 `VoxelShaper.forHorizontal` 旋转，默认几何朝 SOUTH，查找方向为 FACING 的反向，与方块状态的模型旋转一致。智能版仍调用原生舱口形状，避免影响当前斜面过滤槽。

智能版暂不进行结构改造：固定使用原有黄铜机壳与过滤面板几何，过滤坐标及渲染不动；同样取消开合反馈，移除其开启模型。

生成器为 `tools/create-fluid-hatch.cjs`，参数为解压后的 Create 源码根目录。`outputs/fluid-hatch/preview.png` 展示原生舱口、CCD 正面和侧面，`textures.png` 展示铜色框架图集，`model.meta.json` 记录资源来源与变换。仅静态检查与离线渲染，未构建、测试或启动游戏；离线预览不是游戏内验证。
