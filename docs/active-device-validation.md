# 活动设备、渲染、过滤与燃料验证

## 1. 正常世界调度的活动设备采样

使用 GameTest 四条隔离设备通道，正常运行 330 tick；每 10 tick 补充来源与排空目标，执行打包并移走包裹。万向泵周期恢复测试转速（未接真实电机），水龙头向下灌液，打包机实际生成流体包裹，燃烧室储液并供热。打包量为 64000 mB。

使用 `-PdeviceMeasurements` 仅观察指定的四个实体，统计 tick CPU 时间和 sendData 同步请求。`-PsyncBaseline` 对照模式只取消储液同步节流，不回退其他优化，因此不是旧版本完整性能对照。

基础环境同负载结果：万向泵同步请求 570 → 40；水龙头 16 → 16；打包机 48 → 48；原生桶燃料燃烧室 7 → 7。Liquid Fuel 3.0.0 环境燃烧室 353 → 42，万向泵同为 570 → 40。分别减少约 93% 与 88% 的同步请求。

最终优化样本四设备 330 tick 累积 CPU：水龙头 4.2626 ms、打包机 0.4856 ms、万向泵 7.5954 ms、燃烧室 0.9495 ms；同条件取消节流样本为 3.6867、0.4674、7.5959、0.8262 ms。该规模不足以证明 CPU 收益，跨进程 JIT 和测试并行影响显著，不外推整厂 TPS。

sendData 实际调用 ServerChunkCache.blockChanged，由区块更新合并；同步请求数不能等同真实包量。本轮没有连接固定客户端采集线上的包数或字节数，也没有真正完整管网工厂的 TPS 前后对照。测量工具默认禁用，不会在普通运行时计时或收集样本。

活动测试发现并修复水龙头服务端粒子问题：原 FluidFX 辅助类包含客户端类引用，专用服务端活动灌液时可能触发非法类加载；改为直接构造原生 FluidParticleData 并由 ServerLevel 发送。

## 2. 统一渲染姿态

新增 PumpRenderFrame，从 PumpOrientation 的 signed right/up/south 轴生成 Quaternion，红石泵指针、调频泵齿轮与指针共用。消除渲染器中的独立 FACING/ROLL switch。JOML 四元数转换由全部姿态测试验证，其局部 X 与逻辑传动轴一致；前一轮 JSON 矩阵检查继续提供静态资源约定。

未逐姿态操作客户端验收遮挡、透明度、指针初始姿态或动态方向，因此不声称人工视觉验收已完成。

## 3. 产物过滤边界

在 FanProcessing 的掉落物与传送带两个 process 调用入口添加前置检查。当前允许已验证的 Create、CCD（自定义、粘接、打磨、缠魂）与 More Catalysts RecipeApplier 路径。安装产物过滤器时，未知第三方处理类型暂停加工并保留输入；清空过滤后恢复原有处理。这个限制是明确的行为变化，不是自动支持所有第三方处理。

Create 高温加工可无配方销毁物品，因此过滤开启时，只有实际存在可自动化熔炼／高炉配方才进入原生处理，其结果仍由 RecipeApplier 过滤。没有为了预览调用 process、脚本或随机掷骰；概率与副产物保留原规则。动态脚本已有的声明结果要求保持不变。

新增匿名第三方处理器测试，验证传送带计时完成后其 process 不被调用、输入保持不变。未知类型须检查注册表对象身份，不能把默认返回的原生 ID 当成已验证类型。尚未为 Dragons Plus、Garnished 等每种特殊加工确认并登记支持；当前过滤器开启时这些路径可能暂停，需要后续专项适配。

## 4. 燃烧室生命周期

新增熔岩与超级熔岩混合拒绝、储液保存／读取、普通供燃、切换超级燃料、燃烧时间读取、普通燃料排队等测试。Liquid Fuel 按刻消费逻辑增加保护：剩余特殊燃料燃烧时，不提前消耗普通液体或降级 activeFuel。未缓存第三方燃料结果，仍按最新数据查询。

基础环境与实际 Liquid Fuel 3.0.0 环境，最终均 109 项 GameTest 通过。真实数据包将燃料配置改为其他数值后的专项重载、第三方全部燃料及客户端护目镜实时动画不在这次覆盖范围。
