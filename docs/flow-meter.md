# 流量计

`ccd:flow_meter` 继承 Create `FluidPipeBlock` 和 `FluidPipeBlockEntity`，保留原生管道压力传播与流体传输行为。只有两个相对的管口，智能放置对齐邻接管道；扳手改变表盘朝向，潜行扳手拆卸。

主体使用 Create 的 `gauge/base`，表头使用 `gauge/stressometer/head`，指针复用 `GAUGE_DIAL`。两端轴孔改为铜面和原生管口，主体贴图由 Create `gauge.png` 改色，保留刻度和指针区域。资源为上游衍生，并非原创模型／贴图。

工程师护目镜显示 `mB/t`。指针按对数刻度响应，10000 mB/t 达到满量程，数值不受指针量程限制。读数来自上一游戏刻的实际传输量，非压力推算；无流动归零，不保存过期流速。

原生管网在实际执行目标填充后，沿已建立的定向流路径累计经过流量计的传输量；没有流量计的网络跳过路径追踪。路径搜索上限 4096 个节点。在存在多条并联路径／环路的网络中，Create 只维护源到目标的总传输量，无法唯一确定每条支路的实际分流，本实现按首条有效路径归属，不保证这类拓扑的支路精确计量。

缓存泵与创造输液罐在各自实际输送路径上累计流量，不修改其流速、容量或输出模式。配方：应力表 + 流体管道 + 铜锭，无序合成。

验证：Java 编译、资源检查和模型审计通过。GameTest 验证原生泵 64 RPM 经流量计输送水时读数为 32 mB/t，目标装满后归零。62 项测试仅已有 `coarseshapesmatchselection` 失败（智能收集栅形状碎片数）。客户端图形效果尚未复验，JAR 未更新。预览 `outputs/flow-meter/preview.png`。
