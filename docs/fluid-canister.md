# 流体罐

原“流体包裹”的显示名称改为“流体罐 / Fluid Canister”。物品名、提示及相关说明统一使用新名称。注册 ID 仍为 `ccd:fluid_package`，继续继承 Create 的 `PackageItem`，复用地址、运输、物流识别与卸液机制。

主体采用四个简单长方体：铜色罐身、底沿、上盖和密封盖。正面按液滴轮廓切出玻璃观察窗，同一行相邻面合并，避免逐像素堆砌方块。模型边界保持为 X/Z 2–14、Y 0–12，沿用原来的 12×12 包裹尺寸和原生吊索。容量仍为 4000 mB，通过流体打包机卸液。

贴图为原创的 16×16 像素图。使用 pixel-art 技能逐像素绘制，参考本地 Create 6.0.10-280 的铜机壳与流体储罐贴图，采用完整八级铜色、五级中性框架色，以及窗内暗色和玻璃高光，共十五色。重画铜面像素簇、包边接缝和磨损明暗，避免大块平涂。UV 保持一个模型单位对应一个纹理像素，不使用渐变或抗锯齿。

观察窗采用几何开孔、内侧暗色背板和像素玻璃反光。透明部分不绘制面，玻璃没有大块半透明覆盖层，因此适配原生包裹的 solid、cutout 和 Flywheel 实例化路径，不需要更改全局渲染层。

`FluidCanisterModel` 读取实际 `FluidStack` 的静态纹理和颜色，将观察窗模板烘焙为流体面；保留流体纹理动画。液位按容量比例分为二十级，空罐显示内壁，满罐填满窗口。颜色烘焙进顶点，避免原生包裹缓存不读取物品染色的问题；流体在罐内显示为不透明表面。外壳、玻璃高光不受流体染色影响。

物品覆盖模型负责手持、物品栏、传送带及打包机显示；客户端限定的六个小型 Mixin 仅适配原生掉落包裹、锁链、蛙港的模型查找，包含普通渲染和 Flywheel 路径。运输动画、摆动、吊索、光照与物流数据不变。外观缓存按纹理、颜色和液位复用，资源重载时重建；渲染专用键只用于客户端模型表，不写入物品或世界数据。独立 partial 不加入 Flywheel 的资源文件注册表。移液臂的独立载液袋不在本次修改范围内。

`tools/create-fluid-canister.cjs` 使用 Node.js 与 sharp 生成模型、像素贴图及离线预览，参数为解压的 Create 源码根目录。`outputs/fluid-canister/preview.png` 展示三个视角；`textures-source.png` 为原尺寸贴图拼图，`textures.png` 为最近邻放大的像素对照，顺序见 `model.meta.json`。

本次仅进行静态资源检查与离线模型渲染，未构建或启动游戏。离线预览中的蓝色流体为示意，不是运行时水纹理截图；游戏中读取实际流体。离线预览不包含游戏内环境光遮蔽和光影效果。
