# 流体端口与桥接器行为对齐

2026-11-19：根据用户要求，参考 Connected 公开实现所表现的行为，使用 CCD 自有流体解析器重新实现。没有复制 Connected Java 源码；既有 Connected 衍生接口美术的来源与许可保持独立记录。

本文件替代 `fluid-access.md` 中早期原型的代理嵌套、对外开放面、过滤和放置说明。

- 放置时以玩家视线优先顺序寻找相邻、具有流体能力的方块实体；查询空方向以选择目标，实际存取仍遵守目标接触面的能力约束。没有目标时按视线放置，端口的潜行放置反转目标方向，桥接器选择视线轴。
- CCD 保留已有六向 FACING 存档格式。端口 FACING 指向连接容器的反方向；桥接器新放置时规范化为轴负方向，旧方块保持可用。桥接器过滤端与枚举方向绑定，不因旧 FACING 的正负而交换。
- 全部六面共享代理能力。端口、桥接器均只能连接直接容器，不能互相嵌套。没有有效来源时接口为空。
- 红石信号断开所有存取，已有接口引用也即时失效；邻居更新后刷新连接状态。放置、读档初始化和转向重新计算状态，不保存流体副本。
- 比较器：端口转发实际容器输出；桥接器取两端有效容器输出之和的整数一半，缺失端按零计算。
- 连接状态控制凸出连接座是否显示；物品模型仍显示完整连接座。沿用用户当前机壳、接口图片和 UV，不改写贴图。
- 桥接器各端过滤同时限制可见库存、注入与抽出。明确过滤优先于另一端空过滤，即使明确过滤端未连接容器也保留该分类。两端均为空或均明确匹配时，允许两端访问。
- 无槽位参数的流体填充按轴负端、轴正端依次执行，不能照搬物品按槽插入 API；一次抽取可以汇总两端相同流体及组件。
- 保留 CCD 原有真实容器身份去重、Create 多方块控制器识别与流体物流计数作用域，不引入 Connected 桥接器仅用一端代表整体的去重局限。

参考行为来源：Connected `InventoryAccessPortBlock`、`InventoryAccessPortBlockEntity`、`InventoryBridgeBlock`、`InventoryBridgeBlockEntity`；Create 原生 `DirectedDirectionalBlock` 的方向和扳手行为。代码组织、流体存取、失效处理和测试由 CCD 独立实现。

验证：全部 35 项 GameTest 通过，包含邻接容器自动选择、上下放置、潜行反向、扳手面方向、比较器、红石断开与恢复、过滤优先、禁止代理嵌套以及原有物流去重。最后补充机械结构旋转适配后重新构建成功。游戏内完整客户端视觉与机械结构实际旋转仍需实测。
