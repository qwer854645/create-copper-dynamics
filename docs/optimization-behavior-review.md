# 优化后的功能变化复核

对照 alpha.17 版本提交 87d762f 与当前 246a330，结合优化阶段实测记录进行静态差异复核。本轮没有修改业务代码、没有重跑全部测试，结论不等于全组合实机验收。

## 已确认的行为变化

- 三种储液设备同步合并为最多每8tick发送一次储液更新，客户端储液显示可能延迟约0.4秒。服务端实际库存与搬液不等待同步；原生热量状态同步不受该上限全部约束。
- 雾化器设置产物过滤后，未知或未验证处理路径暂停并保留输入；空过滤时保持原有调用。后来补齐的四类附属不能代表所有其他附属都已支持。
- 批量粘接现在也接受产物过滤；以前该路径漏过检查。匹配的是第一条真实粘接配方，不根据目标产物寻找另一配方。
- 高温加工在过滤启用时不再允许无配方销毁物品。存在熔炼／高炉配方的输入仍沿用原生执行和RecipeApplier检查。
- 异常相邻转移无法退回来源时，万向泵优先恢复真实缓存；仍有余量则掉落携带流体的包裹。这是可见恢复行为，正常合规接口无此额外产物。
- 红石泵新增ROLL；两种泵最终采用点击面轴旋转完整姿态，不再固定循环24姿态。原版泵式端面翻转被整机绕轴旋转取代。
- 液体燃料环境中，普通液体不再打断仍在运行的特殊燃料，改为在罐中排队。
- 新增显式流体加工映射可以覆盖内置介质选择；自动标签发现仅在现有识别失败后尝试。具体影响取决于整合包添加的映射，不是默认无条件改变所有介质。

## 需要修正／专项验证的风险

1. 最初便携泵继承父类结构变换时仍缺竖直模型；随后用户明确要求增加竖直支持，eefe8a8 已同步放置、扳手、静态模型、动态风箱和形状，并通过24姿态测试。这个风险已转为明确的新功能。仍需客户端视觉及竖直方向实际手动传动／跨管输液验证，不能只凭形状检查宣称全部验收。
2. ThirdPartyOutputFilters 的 Dragons Plus 兼容回退通过查询 DnD／Garnished 配方模拟选择，而没有完全按上游兼容回调的注册顺序、开关与实际优先级计算。多模组存在重叠配方时可能过度拒绝匹配目标；个别实际分支若未走RecipeApplier，还需验证能否绕过前置判断。已测390条配方并不证明所有冲突组合一致。
3. Dragons Plus染色预览与Liquid Fuel反射API不匹配时会抛异常；“可选”只保证未安装时不加载，不保证升级到任意版本仍安全。需版本边界或可恢复失败策略，避免把未识别API直接变成运行时崩溃。
4. FluidProcessingMappings的静态data快照在服务器退出时没有单独清理（当前只清脚本）。正常新世界资源加载会替换数据，但应补同客户端连续切世界检查，避免生命周期中的旧世界映射被提前读取。API映射则按设计保留。
5. 粘接索引对两原料／黏液球候选作预过滤；标准静态Ingredient在reload失效后保持语义。若第三方Ingredient的test依赖外部动态状态且不触发配方重载，候选可能过期，需要明确不缓存此类Ingredient或采用额外失效机制。

## 预期仅改变开销的项目

- 固定邻居BlockCapabilityCache：容器替换、转向、能力失效已专项检查，第三方若不遵守invalidateCapabilities契约仍可能返回旧视图。
- 万向泵端口对象复用：复用身份改变了对象分配次数，但fill/drain实时检查模式，关闭／切换测试通过；getFluidInTank仍会展示共享缓存，此行为优化前已存在。
- KJS排序快照：排序时机移到规则修改，优先级、删除与reload测试通过，未缓存标签成员。
- Liquid Fuel缓存反射Method：不缓存燃料值，仍读取实时数据；不是永久冻结燃料配置。
- 脚本outputs副本从两次改为一次：返回列表仍是副本，产量计算不变。
- 统一渲染Quaternion：目标是与逻辑坐标轴等价，矩阵／姿态测试通过；人眼遮挡和动画方向尚非自动验证覆盖。

## 未发现这段优化修改的内容

该提交区间没有重写生存配方、储罐额定容量、普通泵基础速率、雾化费用配置或加工概率参数。前期配方平衡与Liquid Fuel接入本身是另一个更早区间的功能变化，不能混称为本轮纯优化。NBT原有Buffer／FuelTank保存键保留。

建议先修便携泵继承边界和可选API失败策略，再做跨模组回退冲突专项。已确认的过滤暂停与显示延迟应作为更新说明明确告知，而不是宣称优化前后完全一致。

## 续查至 eefe8a8

### 现在确认的新增变化

- 便携泵从仅水平变成六个管口方向、四档ROLL；放置依赖视线及管口对接，碰撞／点击范围随实际风箱局部轴压缩。普通手动操作仍右键正转、潜行反转，不改耗饥饿、转速、流量与范围。
- 便携泵原来的世界竖直压板运动改为随局部姿态变换，因此横装／倒装时压缩方向也改变，这是必需外观与碰撞变化。
- 新映射仅决定雾化器处理类型，没有让普通风扇也识别任意新流体；也没有让产物过滤槽自动跨加工类型选配方。此差异属于API边界，不应表述为“所有新模组自动兼容”。
- 未验证加工有过滤器时虽然不转换物品，雾化器仍按原有活跃喷雾周期消耗介质；过滤并非按实际成功加工计费。此为既有费用语义与新暂停保护叠加后的可见结果。
- 调频泵固定24姿态循环仅为中间实现，最终代码已恢复点击面轴旋转。最终使用方法不能沿用中间提交的“连续点任意面可遍历全部姿态”说明。

### 新确认的风险／开销

- PortableFluidPumpBlock.getShape 每次调用构造局部形状、分解方盒、遍历角点并分配数组。碰撞、选择、交互均调用这一方法，新增六方向适配提高了形状查询成本；可将每个实体的精确stroke与BlockState作为缓存键，不能粗量化行程后损失动态碰撞精度。
- 缓存后的万向泵输入／输出handler会在关闭时拒绝fill/drain，但展示方法getFluidInTank仍可通过旧引用看到共享缓存；此行为优化前已存在，不是新增泄漏。第三方若把handler对象身份当物理储罐身份，模式切回后身份稳定会与旧的每次新对象不同，这方面未做PnP组合专项。
- 第三方对象未正确通知invalidateCapabilities时，固定端点缓存可能继续使用旧接口。NeoForge契约要求失效通知，但应在更新说明中保留该兼容前提，不能声称缓存对所有违规模组透明。
- FluidWorldScripts排序快照避免重复分配，却没有减少按规则线性扫描；大量脚本规则时仍随规则数量增长。当前变更不引入流体索引，也不改变源／流动态规则选择。
- 未发现上述区间新增源／流动ID重命名、配方或额定容量调整。红石泵增加ROLL后旧状态默认ROLL=0，但旧世界与第三方保存／旋转工具的完整升级仍未专项验证。

本次续查为静态代码复核，参考最近116项基础测试记录，没有额外重新运行测试；不修改业务逻辑或打包。需要优先处理的仍是第三方回退选择准确性、可选反射API的可恢复失败策略、世界映射清理和便携泵形状缓存。
