# 客户端反馈修正

本轮按用户反馈修正七项问题，只检查源码、依赖字节码签名及资源，并生成离线预览；未构建、运行测试或重启当前客户端。

- 红石阀门：方块和物品模型关闭 ambientocclusion，管口附件包装器使用 Create 的 `PipeAttachmentModel.withoutAO`，避免包装器强制开启 AO，使封闭侧面的角点出现不一致的明暗。保留原有铜纹理、刻度和指针。
- 增压泵放置：移除 CCD 自写的流体连接和轴向放置选择，直接继承 `PumpBlock.getStateForPlacement`。连接优先、视线、潜行反向、含水以及扳手切换 FACING 均用原生实现。
- 增压泵方向与物品：四个动力侧面的轴孔两端各增加一个 3×4 texel 的深铜色小箭头，32×32 动力面图集保持原铜面、轴孔及 UV 比例，箭头指向模型 +Y，随六向 FACING 和扳手反向一起旋转。物品 JSON 组合四段原生 SHAFT_HALF，直接旋转几何并保留对应 UV，世界静态模型不含轴，仍由现有动力绘制器负责。
- 两种龙头：单独覆盖物品 GUI 旋转为 [30,45,0]，正面朝向观察者；不改变世界模型或放置朝向。
- 潮涌箱：原有物品模型已经包含静态原生 cage 和四向 open_eye，水体在后续透明渲染层。将 GUI 旋转改为 [20,25,0]、比例 .7，避开默认对角视角下遮住中央核心的前角柱。世界中的原版动态核心不变。
- 两种流体舱口：撤销全部世界流体能力注册，管道、打包机、供水箱等设备不能再透过贴壁舱口操作后方容器。手持容器和移液臂保留显式 `interactionHandler`，仍按后方容器的实际有向接口操作并遵守智能过滤。`FluidHatchHandheldMixin` 仅在原生 FluidHelper 的两种手持交换方法接收 CCD 舱口时提供显式处理器，其余实体继续查询原有世界能力；已核对调用签名。铜桶的优先交互也使用显式舱口入口，保留创造模式写回装液结果的既有修正。删除舱口链的物流身份转接与过滤变更唤醒管路代码。
- 智能储罐整层放置：继续使用已注册的 Create `FluidTankItem`，不重写批量放置循环。其 private tryMultiPlace 内硬编码查找原版 FLUID_TANK 实体类型，导致 CCD 控制器无法被发现；限定当前物品为 CCD 智能储罐时，改为查找 CCD 的实体类型，并让每次槽位判断只识别 CCD 智能储罐。继续遵守原生规则：在已有 2×2 或 3×3 罐体顶部/底部续接时填充整层，同高度、可替换空间、物品数量、创造模式、潜行单放及对称法杖限制均交给原生处理。原版储罐的类型查找和放置不变。

`outputs/client-fixes/item-models.png` 按实际物品 GUI 角度离线绘制增压泵、两种龙头和潮涌箱，用于确认半轴、正面与核心的可见性；它不是游戏截图。新增 Mixin 的调用目标已与实际 Create 6.0.10-280 依赖 class 文件中的名称和描述符核对。原生管口、轴、刻度和潮涌核心等美术的许可归各上游项目，不另标 CCD 原创。
