# 客户端反馈修正

## 横向智能储罐连接纹理崩溃

用户报告 `crash-2026-11-19_01.50.59-client.txt`：区块网格构建经过 Create `ConnectedTextureBehaviour.Base.getDataType` 时，原生代码以 null sprite 查询连接纹理类型。CCD 横罐 getShift 未处理该合法查询，调用 sprite.contents() 导致空指针。已增加空值判断，查询阶段按面轴选择同为 RECTANGLE 的连接类型；实际贴图阶段仍识别内壁。报告涉及 (38,0,58) 的横罐，不是报告头部 Sable 提示或 FluidLogistics 本身的异常。尚未在用户的完整 Sodium／Iris／Copycats 环境复现验证。

记录最近两轮客户端反馈的修正。本次追加修改仅进行源码、资源检查与离线预览，未重新构建或重启客户端。

- 红石阀门：方块和物品模型关闭 ambientocclusion，管口附件包装器使用 Create 的 `PipeAttachmentModel.withoutAO`，避免包装器强制开启 AO，使封闭侧面的角点出现不一致的明暗。保留原有铜纹理、刻度和指针。
- 增压泵放置：移除 CCD 自写的流体连接和轴向放置选择，直接继承 `PumpBlock.getStateForPlacement`。连接优先、视线、潜行反向、含水以及扳手切换 FACING 均用原生实现。
- 增压泵方向与物品：四个动力侧面的轴孔两端直接引用原生动力泵端圈方向标记，使用 create:block/pump 的原 UV [8,0,6.5,6] 与 rotation=270；两端标记带适配现有机壳的两单位高度，原生图案不改色。动力面恢复 16×16，不保留自绘箭头。标记指向模型 +Y，随六向 FACING 和扳手反向一起旋转。物品 JSON 组合四段原生 SHAFT_HALF，直接旋转几何并保留对应 UV，世界静态模型不含轴，仍由现有动力绘制器负责。
- 两种龙头：单独覆盖物品 GUI 旋转为 [30,45,0]，正面朝向观察者；世界模型与放置朝向不变。碰撞、选中和交互形状改为实际机身与当前手柄状态的组合，随四向 FACING 旋转；智能版还包含正面过滤槽。移除主手必须为空的限制，沿用原版拉杆的物品交互回落路径，普通手持物品也可操作开关，原生过滤和扳手交互仍优先。
- 潮涌箱：原有物品模型已经包含静态原生 cage 和四向 open_eye，水体在后续透明渲染层。将 GUI 旋转改为 [20,25,0]、比例 .7，避开默认对角视角下遮住中央核心的前角柱。世界中的原版动态核心不变。铜框纹理取消原有从左上到右下的强明暗倾斜，四角与折边采用一致色阶，保留较轻的不规则铜面像素簇；所有复合模型继续关闭环境遮蔽。
- 两种流体舱口：撤销全部世界流体能力注册，管道、打包机、供水箱等设备不能再透过贴壁舱口操作后方容器。手持容器和移液臂保留显式 `interactionHandler`，仍按后方容器的实际有向接口操作并遵守智能过滤。`FluidHatchHandheldMixin` 仅在原生 FluidHelper 的两种手持交换方法接收 CCD 舱口时提供显式处理器，其余实体继续查询原有世界能力；已核对调用签名。铜桶的优先交互也使用显式舱口入口，保留创造模式写回装液结果的既有修正。删除舱口链的物流身份转接与过滤变更唤醒管路代码。
- 智能储罐整层放置：继续使用已注册的 Create `FluidTankItem`，不重写批量放置循环。其 private tryMultiPlace 内硬编码查找原版 FLUID_TANK 实体类型，导致 CCD 控制器无法被发现；限定当前物品为 CCD 智能储罐时，改为查找 CCD 的实体类型，并让每次槽位判断只识别 CCD 智能储罐。继续遵守原生规则：在已有 2×2 或 3×3 罐体顶部/底部续接时填充整层，同高度、可替换空间、物品数量、创造模式、潜行单放及对称法杖限制均交给原生处理。原版储罐的类型查找和放置不变。

`outputs/client-fixes/item-models.png` 按实际物品 GUI 角度离线绘制增压泵、两种龙头和潮涌箱，用于确认半轴、正面与核心的可见性；它不是游戏截图。新增 Mixin 的调用目标已与实际 Create 6.0.10-280 依赖 class 文件中的名称和描述符核对。原生管口、轴、刻度和潮涌核心等美术的许可归各上游项目，不另标 CCD 原创。
