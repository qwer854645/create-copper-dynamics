# Create: Copper Dynamics — CCD

机械动力：铜流工程。当前版本：`0.3.0-alpha.1`。

这是首个流体打包原型：继承 Create 的包裹和打包机类，流体直接保存于包裹的数据组件中。
同一个流体打包机从背后的流体容器打包，也将收到的包裹拆进背后的流体容器。

## 运行环境

- Minecraft 1.21.1、Java 21。
- NeoForge 21.1.219 或更新的 21.1 系列；本次验证版本为 21.1.219。
- Create 6.0.10；本次构建针对 Maven `6.0.10-280`。
- 不声明兼容 Create 6.0.11，待对应版本验证后再开放范围。
- 开发运行依赖 Ponder 1.0.82、Flywheel 1.0.6、Registrate MC1.21-1.3.0+67；普通玩家使用正常安装的 Create 及其所需依赖。
- 模组同时安装在服务端和客户端。

## 如何使用

1. 在创造模式的“机械动力：铜流工程”物品栏取得“流体打包机”。生存配方为一列：铜锭、Create 打包机、Create 流体储罐。
2. 将流体打包机贴在储罐上。背面连接容器，正面负责包裹收发；支持六个方向。必要时用扳手调整朝向。
3. 用管道向背后的储罐供液。机器不需要旋转动力，也没有可供管道访问的内部储罐。
4. 红石触发封装；持续供电会按 Create 原生周期继续尝试。生成的包裹未取走时停止封装。
5. 无需设置每包装液量。红石触发时尽可能装入当前可抽取的同一种流体，每包最多 4000 mB，不足一包也会封装；仪表订单按请求量封装，超过容量则分包，最后一包装剩余量。旧存档的每包装液量设置不再生效。
6. 手持有内容的标准流体容器（例如水桶）右击机器，采样并设置过滤；不消耗手持容器中的流体。空手潜行右击清除过滤。过滤包含流体附加数据；该过滤约束红石自动打包，物流订单按请求的流体身份执行。
7. 像原生打包机一样使用相邻告示牌配置包裹地址。
8. 用蛙港、漏斗等取走包裹，或在机器空闲时手动取走。包裹可进入原生蛙港与锁链输送机运输。
9. 收货端用另一台同种流体打包机贴在目标储罐上。将包裹插入机器，或手持包裹右击机器；不需要拆包模式或额外红石信号。
10. 目标容器正常情况下必须能完整接收一包；空间不足或流体不匹配时不接收。佩戴工程师护目镜可查看机器状态、过滤和余液信息。

## 流体包裹地址操作

地址数据和通配符匹配直接使用 Create 的 `PackageItem`，告示牌、仪表订单、蛙港及地址过滤器继续沿用原生规则。

1. 原生剪贴板中，未勾选的 `#地址` 条目是地址簿；可以手动编辑，也可以手持剪贴板右击已配置地址的原生蛙港来添加。
2. 在背包或普通容器界面拿起剪贴板，使它跟随鼠标；**右击槽位中的流体包裹**，复制其地址到剪贴板当前页。当前页已满 12 条时新建一页；已存在的相同条目会取消勾选，不重复追加。
3. **左击槽位中的流体包裹**，粘贴剪贴板当前页唯一未勾选的 `#地址`。有多个不同候选地址时不修改包裹，请先在原生剪贴板界面勾选其他候选地址，或切换页面。普通文字和已勾选条目不参与选择。
4. 单独一条未勾选的 `#` 是显式清除地址标记；空剪贴板不会清除地址。复制没有地址的流体包裹，也会生成该标记。
5. 只读剪贴板可用于粘贴，不能写入。操作只修改原生地址组件，不消耗剪贴板或包裹，也不改变流体、订单编号、分片或在途承诺。已有订单包裹改址可能使其无法到达原收货站，应按实际运输用途操作。

这部分使用标准物品槽点击机制，不新增地址界面或网络包；合装匣暂不扩展。当前仅完成代码静态检查，未构建或运行验证。

## 动力移液臂

继承 Create 原生动力臂，沿用多目标调度、机械臂移动、正放／倒挂、轮询设置及动力网络，交互改为流体容器。以原生动力臂、2 个流体管道、1 个铜机壳无序合成，或从 CCD 创造栏取得。

1. 手持动力移液臂右击容器的具体面，依次设为输入（蓝色）、输出（金色）、取消；潜行右击可直接移除。按所点击面的实际流体接口交互，不能从不支持流体接口的机器或管道强行抽液。
2. 选择完放置移液臂，服务端会应用有效目标并清空手中选择；也可持另一件移液臂右击已放置设备重新配置。潜行右击已放置设备清空其目标及手中选择。跨维度选择不应用。
3. 目标距离沿用 Create 的机械臂距离，输入、输出合计最多 64 个面；过远、未加载或没有对应流体接口的目标不应用。未加载目标不会强制加载区块。手持配置物品可看到选中面的标记，原生扳手查看目标仍可使用。
4. 接入齿轮动力，转速影响移动周期，应力系数与原生动力臂相同（默认 2 SU/RPM）。输出策略直接使用原生轮询、强制轮询、优先首项。红石依照原生规则阻止新取液，已经持有的流体会继续尝试交付。
5. 每次最多取 1000 mB，先模拟输出端可接收量，再实际取液。取液后由爪端持有，送达时按实际接收量扣除；剩余量继续寻找目标，输出堵塞时保留在手中，不重复抽液。
6. 没有独立储罐，也不能对移液臂直接接管抽灌。爪端以透明外壳、流体染色内芯的液囊显示本次在途流体；正常搬运不需要桶或包裹。内部沿用原生 ItemStack 货载及存档，液囊仅用于爪端承载，不提供配方或创造栏入口。
7. 工程师护目镜显示爪端流体名称、真实 mB 数量和工作状态；不再区分储罐存量与在途量。右击卸货或拆机时，液囊转成普通密封流体包裹，保留流体与附加数据；背包已满时按原生库存规则掉落。首次给机械臂戴护目镜仍优先执行原生戴镜操作，不会卸货。

首版处理标准流体容器之间的多源、多目标搬运，不执行传送带注液配方。供液途中不会维持可反复提取的虚拟库存；外部接口模拟与执行不一致时仍保留实际抽出的完整流体。实现只参考 Create 和标准流体 API，未复用三个流体附属的实现代码。

客户端同时接入原生 `ArmRenderer` 和 `ArmVisual`，机械部分沿用原生外观，爪端液囊使用 CCD 自定义物品模型和标准流体颜色。源容器在实际取液时变空会重新寻找输入，避免空手等待输出。当前只完成静态检查，未构建、游戏测试或视觉验证。

## 智能龙头

继承基础铜龙头，增加 **Create 原生流体过滤**与**传送带／置物台物品注液**，没有内部储液。使用铜龙头、黄铜锭和电子管无序合成，或从 CCD 创造栏取得。

1. 背后连接源容器，空手点击非过滤槽区域开启；红石通电暂停。直下方一格的容器／炼药锅供液方式与基础版一致，新增过滤同时约束这条供液路径。
2. 在过滤槽用原生方式选择允许的流体或配置原生过滤器；图标、交互、过滤判定及设置保存使用 `FilteringBehaviour.forFluids()`。
3. 注液加工时，传送带或置物台放在龙头**下方两格**，中间留一格空气，与原生分液池的物品加工位置一致。支持原生 `FillingBySpout` 识别的注液配方、序列装配注液及桶／瓶等可注液物品，不处理地面掉落物或手持物品。
4. 每件物品等待 20 tick；完成时重新检查源流体、过滤及目标物品，按原生所需量一次性抽取后交付结果。单次上限与原生分液池容量一致为 1000 mB。缺液或数量不足时等待，已有允许的流体但无法用于该物品时放行。
5. 关闭、红石暂停或物品不再可加工时放行，已经开始的计时作废；重新开启需重新计时。物品被取走或更换时不交付结果，实际流体抽取失败时不消耗物品。异常流体当场退回源，无法退回则掉落密封包裹，不暂存液体。
6. 加工通过原生 `TransportedResult` 替换物品并保留未处理的输入。计时中不预扣流体；区块重新载入后从头计时，不保存额外物品库存或流体库存。

模型以黄铜外观区分基础铜龙头，过滤图标使用原生方块实体渲染器。当前仅静态检查，未构建或运行；配方匹配、物品停留／放行和显示效果尚未实测。

## 铜龙头（基础版）

从背后的流体容器直接取液，向正下方一格的流体容器或炼药锅供液，无需旋转动力、没有内部储液。合成为 2 个铜锭、1 个流体管道、1 个拉杆的无序合成，也可在 CCD 创造栏取得。

1. 将龙头安装在容器水平侧面，背面的连接座贴着供液容器。正下方一格放接收容器，二者中间不留空格；用扳手可水平旋转龙头、改变供液侧。
2. 默认关闭，空手右击开关。红石通电暂停供液，但保留手动开关状态；断电后若手动开关仍开着，会继续供液。手柄模型与护目镜提示反映实际开启／关闭／红石暂停状态。
3. 每 20 tick 最多转移 1000 mB，沿用原生分液池的加工周期常量。容器可部分接收；目标堵塞、缺失或容量不足以完成原子操作时，不抽走原料。不主动向空气放置流体。
4. 对普通容器查询标准的有向流体接口：源为背面容器朝向龙头的一面，目标为正下方容器的顶面。龙头本身不提供流体容器能力，基础版需要背后有实际容器，不直接从管道网络抽液。
5. 炼药锅读取 Create 的公开 `CauldronSpoutingBehavior.CAULDRON_INFO` 注册信息，默认水每级消耗 250 mB、熔岩填满消耗 1000 mB，满锅不再注入。注册的流体与单次用量决定能否操作，超过本机单次上限时等待。
6. 执行结果与模拟不一致时，未交付的流体立即尝试退回源，退不回的部分掉落为密封流体包裹，不暂存在龙头里。实际成功供液才播放原生流体粒子。

本版不处理手持桶、掉落物或传送带物品，不执行注液配方；这些属于后续智能龙头的物品注液功能。已阅读 Create 的分液池、物品注液与方块注液实现；基础龙头不继承其内置储罐和传送带加工逻辑。当前只静态检查，未构建、运行或验证显示效果。

## 红石三通阀门

三个固定管口呈 T 形：银色公共口 C，对面的直通口 A，以及垂直于直通轴的侧口 B。**无红石信号接通 C ↔ A，有信号接通 C ↔ B**；未选中的支路关闭，A、B 不直接互通。通路允许双向流动，实际方向由泵决定，因此可切换输送目的地或流体来源。

1. 在 CCD 创造栏取得，或将红石流体阀门、一个流体管道和一个铜机壳无序合成。
2. 贴着管路放置时，公共口朝向所点击的支撑方块，直通口朝外。绿色端口标识当前选中的 A 或 B，银色始终标识 C。
3. 用扳手点击直通轴两端的面，循环调整侧口的四个朝向；点击其他面，绕所点面的轴旋转整体。支持 24 种空间朝向，保留含水、结构旋转和镜像关系。潜行扳手按原生方式拆除。
4. 任意相邻面提供红石信号都切换到侧口，信号强度不调节流量。无需旋转动力、不提供压力、不存液，也不暴露独立流体容器接口；需由机械泵或增压泵驱动管路。
5. 切换及旋转后重建有效连接，清理旧连接网络，并通知邻近管路和泵重新计算压力；拆除和区块重新载入也会刷新。此过程按管网更新时序完成，不承诺红石边沿内零延迟切换。
6. 护目镜显示直通／侧通。首版不包含同时分流、比例分配或额外全闭模式。使用原生流体管网的混液与接口规则。

模型由铜制主体和三个开孔管口组合，管道连接附件复用原生 `PipeAttachmentModel`。当前仅完成静态检查，未构建、运行或进行视觉验证。

## 红石流体阀门

直接继承 Create 原生流体阀门及其方块实体：**有红石信号开启，无信号关闭**，不需要旋转动力。配方为原生流体阀门与红石中继器的无序合成，也可在 CCD 创造栏取得。

- 放在管路中，沿用原生阀门的方向、管轴、扳手调整、碰撞形状和含水支持。关闭时由原生管道行为阻止流体通过，仍需泵提供管道输送压力。
- 红石控制原生指针，开关切换在阀门 tick 中完成，通断及管网刷新由原生逻辑处理。放置、邻居变化及区块重新加载时读取实际红石信号；信号强度只区分有／无，不调节流量。
- 不接入传动轴、不占用旋转应力，没有内部储液或独立流体容器接口。
- 阀体、指针、管道连接附件以及 Flywheel Visual 均复用原生资源和实现，护目镜显示当前开关及控制说明。当前外观沿用原生阀门。

仅新增一个读取原生指针字段的 Mixin Accessor，未重写管道传输或关闭判定。本轮只静态检查，未构建或运行验证。

## 流体传输器

用于相邻容器之间的直接转移，无需旋转动力。绿色口朝向输出容器，对面的铜色口连接输入容器；支持六向放置，扳手切换进出方向。配方为 1 个漏斗、2 个流体管道、2 个铜锭，也可从 CCD 创造栏取得。

- 完全没有内部储液、缓冲容量或储液数据存档，也不对外提供流体容器接口。设备直接查询两端容器的标准有向 `IFluidHandler`，先模拟可抽取量与可接收量，再转移双方允许的数量；目标不接收就不抽液。
- 每周期最多转移 250 mB，周期沿用 Create 的 `defaultExtractionTimer`（默认 8 tick）。四个侧面的过滤槽直接使用原生 `FilteringBehaviour.forFluids()`。
- 同向首尾相接可组成最多 64 台的直线通路，由最靠近出口的一台统一调度，整条通路共用转移限额，不按设备数量倍增。全部设备都必须满足各自的过滤要求；任一台红石通电即阻断通路。
- 侧向或反向相接、端点缺失、途经未加载区块及超长通路均不执行转移，不强制加载区块。设备不提供管道压力，外接泵不能将它当作储罐填充或抽取。
- 执行结果偏离模拟时，未交付流体立即尝试退回本次源容器；源也拒收时，就地掉落为密封流体包裹。异常结果不留在设备中，不增加余液恢复状态。接口行为仍以第三方正确报告操作结果为前提。
- 护目镜显示直接转移、周期和红石状态；拆机本身没有内部流体可掉落。

本轮参考了原生漏斗与智能流体管道，直接转移与整链调度由 CCD 自行实现，未复用三个流体附属的实现代码。当前仅静态检查，未构建或运行。

## 增压泵

继承 Create 原生机械泵，使用同一套管道压力传播、分支分配和真实流体转移机制。默认应力是原生泵的 **1.5 倍**，同转速泵送压力为 **2 倍**，每侧作用距离为 **2 倍**。跟随 Create 默认配置时，基础应力系数为 6、每侧距离为 32 格；64 RPM 时占用 384 SU，原生泵为 256 SU。

1. 在 CCD 创造栏取得增压泵；合成需要 1 个原生机械泵、2 个齿轮箱、2 个铜机壳。
2. 绿色管口是出口，对面是入口；沿这一轴连接管道或流体容器。支持六个方向，扳手沿用原生泵的反向操作。
3. 其他四面都有可连接传动轴的轴口，内部为 1:1 转向传动。优先贴着管道放置；没有流体连接时，自动朝向会尽量避开已有传动轴。潜行放置保留原生手动朝向规则。
4. 四个轴口属于同一台动力设备，应力只计算一次；它们也能传递动力。多路动力的转速及转向必须满足内部传动关系，冲突继续由 Create 处理，输入转速不相加。
5. 提高的是原生压力输入，不虚增显示转速，也不额外执行一套抽液逻辑。典型无瓶颈单管路同转速流量约为原生两倍；分支、低速整数取整和容器接口限速会影响实际值。
6. 护目镜显示原生应力占用、每侧作用距离、压力倍率和接口说明。基础模型使用铜制外壳、真实开孔的接口环及原生旋转半轴；本次没有运行视觉检查。

CCD 服务端配置位于世界的 `serverconfig/ccd-server.toml`，`boosterPump` 下分别为 `stressMultiplier = 1.5`、`pressureMultiplier = 2.0`、`rangeMultiplier = 2`。应力倍率乘在 Create 当前机械泵应力系数上，距离倍率乘在其当前泵距上，整合包修改原生值后仍保持倍率关系。配置标记为需要重进世界生效。

管道变更的泵发现搜索会覆盖增压泵距离，用于远端新接管道时重新计算；普通机械泵自身的压力和作用距离不变。当前只完成源码、接口签名和资源的静态检查，未构建、测试或启动客户端。

## 流体工厂仪表（0.2 新增）

流体仪表直接继承 Create 的 FactoryPanelBlock、FactoryPanelBlockEntity 和 FactoryPanelBehaviour；配置界面继承 FactoryPanelScreen。四格布局、安装、调频、连接、库存查询、补货时序和在途承诺沿用原生实现。

1. 在货源流体打包机上安装原生存量转信器。用其他存量转信器调频到同一网络，可以将多个货源接入同一物流网络。
2. 手持“流体工厂仪表”右击该存量转信器进行调频。仪表配方：普通工厂仪表、铜锭、流体管道，无序合成。
3. 将仪表安装在普通表面时，它监控所调频网络。手持装有流体的桶、容器或流体包裹点击面板选择流体；不消耗流体。
4. 将已调频仪表安装在**收货端流体打包机**上，则沿用原生补货模式，维持其背后储罐的目标流体存量。
5. 长按使用原生快速数值选择器（mB／B）；点击已设流体的面板打开原生配置界面。新增的“目标 mB”输入框可精确设置 0–100000 mB，点“设定”应用；0 为只监控。
6. 在原生配置界面设置收件地址和在途承诺过期时间。收货端蛙港地址必须与请求地址匹配。
7. 货源收到原生 PackagingRequest 后立即抽取真实流体并生成包裹，超过当前输出位置的包裹进入 Create 原生待发队列。待发流体已从储罐移出，避免重复当作可用库存。
8. 原生在途承诺用于避免重复补货；流体入库正增量会通知原生承诺队列。界面和悬浮显示统一使用 mB。
9. 一格方块仍可放四个流体面板，每个面板各自调频与选择流体。

原生资源接口只认识 ItemStack，因此有一个仅用于身份适配的“流体识别标记”（1 个计数 = 1 mB）。CCD 不把它生成为实际货物、不把它放入包裹、不通过储罐对外暴露可提取的虚拟物品。实际流体包裹仍直接保存 FluidStack。

Create 储罐按多方块控制器去重；第三方跨多个方块实体代理同一存储的容器尚需专门身份适配。原生物品工厂仪表与流体仪表不混放在同一方块中。

实现依据和复用范围见 `docs/create-reuse.md`。本轮按用户要求只编译打包，不启动游戏或测试；不把此前 0.1 的游戏测试结果作为 0.2 实测结论。

## 合装匣（0.3 新增）

原生理包机的订单到齐检查继续使用 Create 的实现。对同一订单中的 CCD 流体与物品，扩展帮助器会整理为“合装匣”：原生 9 个物品槽位，加上独立保存的流体数据，初始合计容量 8000 mB、最多 8 种流体；超出时生成多个匣子。

使用原生库存管理器等入口在同一次订单中请求物品和流体，汇集到合装站库存，再由原生理包机处理。不同订单即使地址相同也不合并。理包机相邻告示牌可设置出站地址，运输继续使用原生蛙港与链条。

创造栏有有效示例匣。当前潜行打开会归还普通物品，并将流体还原为密封流体包裹；自动混合拆包与分流是功能列表下一项。详细实现、数据边界与使用方式见 `docs/composite-case.md`。

## 数据与异常处理

- 每包一种流体，不堆叠，不保存“内罐物品”，保留完整 FluidStack 组件。
- 封装后不能通过物品流体接口直接抽液或追加灌装。潜行打开只提示使用机器，不撕开空包裹。
- 流体包裹从原生随机外观池与默认普通包裹集合中移除；仍通过 `PackageItem` 继承被原生物流识别。
- 普通物品打包机拒收 CCD 流体包裹，避免把它当作空物品包裹消耗。
- 0.3 起原生理包机可以把完整的 CCD 流体／物品订单整理成合装匣。无效、重复或无法识别的混合内容保留在输入库存中。合装匣的自动拆包尚未实现，当前可手动打开为物品和密封流体包裹。
- 模拟填充与真实填充不一致时，未被接收的流体存入恢复数据。机器暂停收发，并尝试回流背后的容器。
- 恢复数据参与存档保存，拆机时转成流体包裹掉落。实际抽取结果流体身份不符或超出容量／订单上限时同样保留、回流。
- 水不会按纸箱规则破坏密封包裹。普通攻击破包时产生可拾取的原内容物品；恢复物品可继续作为包裹运输。火焰、爆炸和虚空等明确销毁路径不提供流体恢复保证。
- 上述保证面向遵守标准流体接口的设备，不声称能修复其他模组在接口内部自行复制或销毁资源的错误。

## 首版边界

- 已实现：尽量装满／按订单封装、流体过滤、双向打包拆解、地址、原生收发动画、护目镜信息、基础模型、中文与英文、配方与掉落。
- 已新增：继承工厂仪表的流体仪表、原生物流网络中的 mB 库存摘要、按目标存量自动请求、原生待发队列和在途承诺。
- 0.3 新增：原生理包机合并同订单物品与流体货物，输出可承载多种流体的合装匣；纯物品订单保持原生路径。尚未实现自动混合拆包与分流，以及第三方包裹格式转换。
- 客户端美术是使用原生资源引用和自定义模型组合的功能原型。当前源码补齐了流体包裹与合装匣的原生局部模型、锁链吊索模型注册，并恢复打包机框架的透明孔洞与 cutout_mipped 渲染层；本次仅静态检查，未编译或进行视觉实测。
- 未复制 Repackaged、Create: Fluid 或 FluidLogistics 的实现代码；运行依赖与 API 复用来自 Create、NeoForge。
